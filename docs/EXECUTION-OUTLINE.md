# Execution outline — Demo → Discovery → Live build → Pilot → Handover

## 1. Demo (done — this zip)
Landing page + chatbot demo with staff desk, built from verified facts only. Show it to the clinic, do not present it as live.

## 2. Discovery (before any live build)
Ask the clinic to confirm in writing:
- Services + exact prices, deposit policy, cancellation policy
- Weekly hours per branch, doctor availability, slot length
- Calendar access (Google Calendar / paper diary / Fresha?)
- Instagram + Facebook access, WhatsApp number for alerts
- Who is reception (who approves bookings?), who handles price questions?
Publish nothing until the owner says yes.

## 3. Live build (3–5 days, after discovery)
- One-page site + chatbot, knowledge base built ONLY from discovery facts.
- Real database + staff login + slot management + alerts.
- WhatsApp is a separate phase — website chatbot first, WhatsApp after.

## 4. Pilot (2 weeks)
- Track: chats started, leads captured, bookings requested, bookings confirmed.
- Kill rule: fewer than 5 real bookings in 2 weeks → review the offer / flow, do not keep charging.
- Weekly check-in with the clinic.

## 5. Handover
- Clinic owns: domain, Vercel/hosting account, Instagram, lead log, knowledge base.
- Hand over: admin logins, how to approve bookings, how to block slots, how to update prices.
- Monthly care (optional): updates, new FAQs, monthly report. Price [TBC].
